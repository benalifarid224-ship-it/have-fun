UPGRADE PROMPT — HAVE FUN V1 → V2
==================================

I already have the Have Fun mobile application.

The current application works, but it feels too basic.

I want you to redesign and upgrade the experience so that users become CURIOUS about what is happening and actually WANT to click on events.

Do not throw away the existing concept or visual identity.

Keep everything that already works, but make the application significantly more immersive, emotional, dynamic and premium.

==================================================
1. CORE EXPERIENCE
==================================================

The current app is an event discovery application.

Its purpose is:

"I'm bored. What can I do?"

The app discovers interesting activities and events around the user and tells them about them.

The goal is NOT to keep users inside the application.

The ideal journey is:

NOTIFICATION
↓
CURIOSITY
↓
EVENT PREVIEW
↓
"WHAT IS THIS?"
↓
OPEN EVENT
↓
GET EXCITED
↓
SEE LOCATION / TICKET / DETAILS
↓
LEAVE APP
↓
GO HAVE FUN

The app should feel like it is constantly saying:

"Something is happening.
Come with us.
Have fun."

==================================================
2. THE BIGGEST CHANGE: MAKE EVENTS FEEL ALIVE
==================================================

The current event cards are too static.

Do not make events feel like calendar entries.

An event should feel like an EXPERIENCE.

When a user sees:

Football
Music
DJ
Drift

etc.

The user should think:

"I want to see this."

4. AUDIO SYSTEM
==================================================

Add an optional event audio system.

IMPORTANT:

Do NOT use copyrighted music without proper licensing.

Build the architecture so every event can have:

audio_url
audio_enabled
audio_volume
audio_preview_duration

The audio should be short and atmospheric.

The user should NOT be forced to listen to audio.

Provide:
- sound on/off
- mute control
- respect device mute settings
- sensible default volume

Do not automatically play loud audio when the app opens.

Audio should be triggered in an intentional way, for example:
- entering an event preview
- opening an event detail page
- tapping an audio/play button

The audio should enhance the experience rather than annoy users.

18. AUDIO PERFORMANCE
==================================================

Audio must not destroy the user experience.

Requirements:

- audio must be optional
- default to reasonable volume
- allow mute
- stop audio when leaving the event
- do not play multiple tracks simultaneously
- avoid unnecessary downloads
- preload only when appropriate
- use compressed audio
- handle failed audio gracefully

If audio cannot load, the event must still work perfectly.
